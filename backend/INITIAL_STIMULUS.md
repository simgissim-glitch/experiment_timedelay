# 최초 질문·답변 통제

## 설정과 구분

`backend/stimuli/development.json`은 DB_ENV=test 전용 가상 제품 자극물입니다. 가상 측정기 루멘 T1의 배터리 한 개가 4시간이라는 설정에서 두 개의 총 사용 시간을 12시간이라고 답하는 계산 오류를 개발 검증용으로 사용합니다. 올바른 계산은 8시간입니다. 실제 제품 사양·출처·실제 연구 자극물을 의미하지 않습니다.

`backend/stimuli/research.json`은 실제 연구용 질문·고정 답변·핵심 오류 식별자·정답 기준·버전의 TODO 파일입니다. approved=false이며 미확정 상태에서는 서버가 사용을 거절합니다. 테스트 자극물로 자동 대체하지 않습니다. 연구자는 실제 자극물과 버전을 확정하고 TODO를 제거한 뒤 approved=true로 설정해야 합니다. 별도의 기존 연구 적격성·동의 정책 차단은 유지합니다.

설정 파일은 서버에만 있고 public에 제공하지 않습니다. 참가자에게는 첫 질문과 공개 시각이 된 답변만 보입니다. 버전·정답·오류 식별자·조건·조작 안내를 API 응답에 포함하지 않습니다. 테스트 내용 자체의 가상 제품 표시는 유지합니다.

## 처리

첫 작업 화면 조회에서 동일한 질문을 읽기 전용 입력창에 제공하고 기존 전송 버튼으로 시작합니다. 클라이언트에서 입력창을 고쳐도 서버 DB 함수가 다른 최초 질문을 거절합니다. 질문을 자동 전송하거나 참가자 ID를 프론트엔드에서 생성하지 않습니다.

서버는 최초 질문·답변 전체와 SHA-256·버전을 DB에 보존하고 참가자와 연결합니다. 같은 연구 DB에서 다른 텍스트나 버전이 섞이면 거절합니다. 진행 중 파일을 바꿔 기존 자극물을 덮어쓰지 않습니다. 새로운 연구 자극물을 배포할 때에는 별도 연구 DB/연구 회차를 준비하고 연구자가 검토한 마이그레이션으로 배포 대상을 명시해야 합니다. 단순 파일 교체로 이미 진행한 연구 자료를 바꾸지 않습니다. 설정 변경 후 서버 재시작이 필요합니다.

최초 답변은 OpenAI를 호출하지 않고 DB에 보존된 고정 텍스트를 그대로 저장합니다. 기존 지연·본문 공개 기한·동일 출력 속도·중복 방지 코드를 그대로 거칩니다. A/B/C는 DB에 배정된 2·9·20초만 다르며 자극물 선택에는 조건을 사용하지 않습니다. 첫 답변 전체의 표시 완료 기록 전에는 새로운 후속 질문을 서버에서 거절합니다.

이후 입력창을 자유 입력으로 전환하고 기존 공식 OpenAI SDK로 후속 응답을 생성합니다. 고정 첫 질문과 첫 답변을 포함한 실제 DB 대화 기록을 전달합니다. 오류를 반복하라는 지시나 정답을 숨기라는 지시는 없으며 기존 시스템 안내는 오류 지적 시 검토·인정·정정을 허용합니다. 정정 여부는 모델 출력에 달려 있고 항상 정정한다고 보장하지 않습니다.

## DB와 로그

`006_initial_stimulus.sql`을 기존 001~005 뒤에 적용하고 웹 검색용 007과 행동 기록용 008도 이어서 적용합니다. 서버는 schema_version=10을 요구합니다.

| 테이블/필드 | 용도 |
| --- | --- |
| stimulus_versions | 질문·고정 답변 원문, 환경, 버전, 해시, 오류 식별자, 정답 기준 |
| stimulus_deployment | 해당 연구 DB에서 사용할 단일 버전 |
| participant_stimuli | 참가자별 버전과 최초 request_id 연결 |
| chat_requests.answer_origin / stimulus_version | fixed_initial 또는 live_llm 및 고정 답변 버전 |
| chat_messages.content | 실제 제공된 질문·답변 원문 및 순서 |
| initial_display_started_at | 첫 글자 표시 확인 시각 |
| initial_exposed_at | 고정 답변 전체 출력 완료 시각; 읽거나 이해했다는 판정은 아님 |
| exposure_delivery_id | 표시 확인을 발생시킨 시도 |
| correction_status | not_assessed / corrected / not_corrected / unclear |
| correction_message_id / correction_assessed_at / correction_assessor_id | 후속 정정 근거 메시지·판정 시각·판정자용 필드 |

노출은 기존 브라우저 표시 이벤트로 자동 기록합니다. 정정 필드는 기본 not_assessed이며 자동 분류나 관리자 판정 쓰기 API는 이번 단계에 추가하지 않았습니다. 단어 일치만으로 정정 성공을 기록하지 않습니다. 향후 확정된 코딩 기준과 관리자 인증을 연결할 수 있습니다. 참가자에게 이 필드를 받거나 보여 주지 않습니다. 연구 DB 마이그레이션 계정 외에는 직접 변경하지 못하도록 RLS와 기존 관리자 읽기 권한을 적용합니다.

기존 005 이전/통제 적용 전 이미 대화한 참가자를 소급해서 오류 노출로 표시하지 않습니다. 이들은 새 통제 세션으로 자동 전환하지 않고 거절하므로 개발 검증은 새로운 테스트 세션에서 수행하세요. 기존 ID·조건·대화는 삭제하거나 변경하지 않습니다.

## 확인

- `node --test tests/stimulus.test.js`: 격리 PostgreSQL과 공식 SDK의 HTTP 대역으로 A/B/C 고정 문구, 지연, 버전, 선공개 차단, 중복·복원, 노출 로그, 후속 문맥, 변경 혼입·권한을 검증합니다.
- `node --test tests/browser.test.js`: Chrome으로 읽기 전용 첫 질문 → 고정 답변 → 자유 입력 후속 정정 → 새로고침 복원 및 기존 화면 진행을 검사합니다. AI는 테스트 대역입니다.
- `npm.cmd run stimulus:check`: 개발 가상 자극물 문맥과 오류 지적을 실제 설정 모델에 한 번 전송합니다. API 사용료가 발생하며 실제 답변을 출력합니다. DB 쓰기는 하지 않습니다.

기존 일반 채팅·지연 회귀 테스트의 서비스 주입은 통제 전 엔진을 따로 검사하기 위해 getStimulus를 생략합니다. 실제 server.js는 항상 DB 환경에 해당하는 자극물 로더를 주입하며 참가자가 이 동작을 끄는 설정은 없습니다.
