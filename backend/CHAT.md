# 일반 AI 대화

최초 답변은 서버 설정의 고정 텍스트를 사용하고 후속 대화는 공식 OpenAI Node SDK의 Responses API를 Express 서버에서만 호출합니다. 모델과 키는 프로젝트 `.env`의 `OPENAI_MODEL`, `OPENAI_API_KEY`에서 읽습니다. 현재 선택 모델은 `gpt-6-luna`입니다. 브라우저·응답 JSON·애플리케이션 로그에 키나 원본 API 오류를 출력하지 않습니다. SDK 로그와 자동 재시도도 끕니다. [최초 자극물 문서](INITIAL_STIMULUS.md)를 참고하세요.

## 실행

1. 테스트용 Supabase PostgreSQL에 001~010 SQL을 순서대로 적용합니다. 마이그레이션은 관리자 계정으로 적용하고 서버는 ai_latency_app 역할의 최소 권한 계정을 사용합니다.
2. `.env.example`을 참고해 기존 `.env`에 TEST_DATABASE_URL, APP_ORIGIN, OPENAI_API_KEY, OPENAI_MODEL을 설정합니다. 기존 비밀키를 덮어쓰지 마세요.
3. `npm.cmd run db:check`와 `npm.cmd run ai:check`로 각각 연결을 확인합니다. AI 점검은 짧은 실제 질문 두 번을 보내며 사용료가 발생합니다. DB 저장을 검사하는 명령은 아닙니다.
4. `npm.cmd run dev` 실행 후 동의·개발 적격성 확인·사전 설문·과제 안내를 완료하고 작업 화면에서 메시지를 보냅니다. Ctrl+Enter 또는 전송 버튼을 사용합니다.

실제 연구 적격성·동의서·개인정보 정책은 연구자 확정 전 TODO이며 연구 환경 등록 차단을 유지합니다. 실제 연구 시작 전 외부 AI 제공자에게 대화가 전송되는 내용도 확정된 동의서에 반영해야 합니다.

## 저장과 문맥

HttpOnly 세션과 작업 화면 접근 권한을 검증합니다. 클라이언트는 참가자 식별자를 보내지 않습니다. UUID request_id는 메시지 전송의 중복 방지용이며 참가자 ID나 실험 조건이 아닙니다.

사용자 메시지와 요청을 원자적으로 저장한 뒤 최초에는 고정 답변을, 후속에는 API 응답을 순서 번호와 함께 DB에 저장합니다. 대화 조회는 본인 데이터만 반환하고 모델·조건·초·토큰을 포함하지 않습니다. 고정 최초 질문·답변을 포함한 이전 성공 대화와 현재 사용자 질문을 DB에서 읽어 후속 요청의 input에 전달합니다. 실패한 이전 요청은 API 문맥에서 제외합니다. 통제 적용 전 이미 대화한 참가자를 소급 전환하지 않습니다. 사용자 지적에 따라 근거를 재검토하고 오류를 정정할 수 있습니다. 최초 가상 자극물과 연구용 TODO는 [최초 자극물 문서](INITIAL_STIMULUS.md), 공개 기한은 [응답 지연 문서](RESPONSE_TIMING.md)를 참고하세요.

`store:false`로 API 응답 객체의 저장을 끕니다. 이 설정이 제공자의 모든 보안·법적 보관을 없애는 것을 뜻하지는 않습니다. 대화는 이 앱의 연구 DB에 저장합니다.

## 요청과 실패 처리

GET `/api/participant/conversations`는 `{messages, requests}`를 반환합니다. POST는 `{request_id, message, retry?:boolean}`를 받습니다. 성공 응답은 `{request_id,status,messages,requests}`입니다. 메시지는 최대 10,000자이고 문맥 합계가 120,000자를 넘으면 임의 삭제 대신 413으로 거절합니다.

같은 전송 키와 내용으로 요청하면 기존 완료 결과를 재사용합니다. 진행 중이면 202이며 추가 API를 호출하지 않습니다. 기존 실패 요청의 반복 POST는 저장된 failed/interrupted 상태를 200으로 반환하며 성공 답변을 뜻하지 않습니다. 실제 재호출은 명시적인 retry:true만 허용합니다. 참가자별 동시에 한 요청, 요청당 최대 3번의 시도, 참가자별 분당 5번·총 100번, 전체 분당 60번·동시 10번을 DB 함수에서 제한합니다. 이는 개발용 API 비용·중복 방지 한도이며 실험 지연 조건이 아닙니다. 운영 한도 변경 시 004 배포 후에는 별도 후속 마이그레이션을 작성하세요.

429·연결 실패·권한 오류·60초 제한·불완전 응답은 안전한 오류 코드로 기록하고 완성 답변으로 저장하지 않습니다. 연결이 끊겨도 서버 작업은 완료하며 다른 탭·새로고침은 기존 DB 요청을 조회합니다. 요청 중단 버튼은 숨기고 기존 자발적 참여 중단 기능을 유지합니다. 서버 비정상 종료로 남은 요청은 2분 임대 만료 후 중단으로 표시하고 재시도할 수 있습니다. 시간 표시나 조건별 안내는 없습니다.

동일 실패 요청 재시도는 최신 질문에만 허용하고 사용자 메시지를 다시 만들지 않습니다. 오래된 시도의 늦은 결과와 참여 중단 이후 결과도 답변으로 저장하지 않습니다. DB 저장 실패 시 성공 응답으로 대체하지 않습니다. 외부 API가 요청을 처리한 뒤 연결이 끊긴 경우 과금 여부는 확정할 수 없으며 명시적 재시도는 새 API 호출이 될 수 있습니다.

## 검증

`node --test tests/chat.test.js`는 격리된 PGlite PostgreSQL과 공식 SDK의 테스트 HTTP 응답으로 저장·문맥·동시 요청·재시도·권한·호출 제한·오류·중단을 검사합니다. `node --test tests/browser.test.js`는 Chrome 임시 프로필과 대역 AI로 화면 전송 및 새로고침 복원을 검사합니다. 이 두 검사는 실제 Supabase 또는 실제 API 연결 성공을 뜻하지 않습니다.
